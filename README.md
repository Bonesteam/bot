# SMC Trading Bot — Binance Futures

Бот для автотрейдингу на Binance Futures за концепцією Smart Money
(структура ринку, Order Blocks, Fair Value Gap, Liquidity Sweep) на
таймфреймі 1H. Сам сканує графіки по списку монет, знаходить сетапи,
надсилає їх у Telegram і (за бажанням) сам відкриває угоди з керованим
ризиком.

## Швидкий старт (локально)

1. Встановіть залежності:
   ```
   pip install -r requirements.txt
   ```

2. Скопіюйте `.env.example` у `.env` та впишіть свої дані:
   ```
   cp .env.example .env
   ```
   Ключі беруться з **Binance Demo Trading** (не окремий testnet-сайт —
   Binance об'єднав це зі звичайним акаунтом): увійдіть на binance.com,
   перейдіть у режим Demo Trading (More → Demo Trading, або
   demo.binance.com/futures), і там створіть API-ключ через звичайний
   API Management — він автоматично прив'язується до віртуального балансу.

3. Перевірте підключення:
   ```
   python main.py
   ```
   Має показати віртуальний баланс і останні свічки BTC/USDT.

## Файли проєкту

### Аналіз (без торгівлі)
- `config.py` — конфігурація, читає `.env`
- `binance_client.py` — підключення до Binance Futures (Demo/Live)
- `smc_structure.py` — swing points, BOS/CHoCH
- `smc_zones.py` — Order Blocks, Fair Value Gap, Liquidity Sweep
- `smc_setup.py` — поєднує структуру + зони в готовий сетап (entry/SL/TP)
- `analyze_structure.py` — показує поточну структуру ринку
- `find_setup.py` — показує всі знайдені сетапи + актуальний зараз

### Бектест
- `backtest.py` — симуляція угод на історичних даних
- `run_backtest.py` — запускний скрипт з підсумковою статистикою

### Сповіщення та трекінг
- `telegram_notifier.py` — відправка повідомлень у Telegram
- `signal_tracker.py` — логує кожен сигнал, сам перевіряє SL/TP на
  наступних свічках, рахує win rate / profit factor
- `check_stats.py` — перегляд статистики трекера в будь-який момент
- `check_pnl.py` — теоретичний $ результат на основі трекера
- `backfill_tracker.py` — одноразова міграція старих сигналів у трекер

### Моніторинг і автоторгівля
- `monitor.py` — безперервний цикл: сканує `WATCHLIST`, шле сигнали в
  Telegram, трекає результати. НЕ відкриває угоди.
- `risk_manager.py` — денні ліміти (макс. угод/день, макс. збиток/день)
- `trade_executor.py` — розрахунок розміру позиції + відкриття угоди з SL/TP
- `auto_trade.py` — повна автоторгівля: усе з `monitor.py` + реальне
  відкриття угод на Binance, якщо `AUTO_TRADE_ENABLED=true`

### Для GitHub Actions (хостинг без свого ПК)
- `run_once.py` — один цикл `monitor.py` (тільки сповіщення) без
  нескінченного циклу
- `run_once_autotrade.py` — один цикл `auto_trade.py` (з реальними
  угодами, якщо увімкнено) без нескінченного циклу

## Локальний запуск

```
python main.py              # перевірка підключення
python analyze_structure.py # структура ринку однієї пари
python find_setup.py        # сетапи по одній парі
python run_backtest.py      # бектест на історії
python monitor.py           # безперервний моніторинг + сповіщення (Ctrl+C для зупинки)
python auto_trade.py        # моніторинг + РЕАЛЬНІ угоди на testnet (Ctrl+C для зупинки)
python check_stats.py       # статистика трекера
python check_pnl.py         # теоретичний $ результат
```

## Telegram-бот (5 хв)

1. У Telegram знайдіть **@BotFather**, напишіть `/newbot`, дайте ім'я і
   username → отримаєте `TELEGRAM_BOT_TOKEN`.
2. Напишіть своєму новому боту будь-яке повідомлення.
3. Відкрийте в браузері:
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
4. У відповіді знайдіть `"chat":{"id": ЦИФРИ` → це `TELEGRAM_CHAT_ID`.
5. Впишіть обидва значення у `.env`.

## Ризик-менеджмент (вбудовано в auto_trade.py)

- **`RISK_PER_TRADE_PCT`** — скільки % балансу ризикувати на угоду
  (розмір позиції рахується так, щоб втрата на SL = точно цей %)
- **`LEVERAGE`** — плече для ф'ючерсів
- **`MAX_TRADES_PER_DAY`** — ліміт кількості угод на день
- **`MAX_DAILY_LOSS_PCT`** — якщо денний збиток (від TOTAL балансу,
  не FREE) перевищив цей %, бот зупиняє нові угоди до завтра
- **`AUTO_TRADE_ENABLED=false`** за замовчуванням — потрібно свідомо
  увімкнути
- **`LIVE_TRADING_CONFIRMED`** — окремий явний прапорець, без якого
  бот відмовиться торгувати на реальному (не testnet) акаунті

## Безкоштовний хостинг 24/7 через GitHub Actions

Замість того щоб тримати скрипт увімкненим на своєму комп'ютері,
можна запускати бота через GitHub Actions — безкоштовний сервіс, який
сам виконує код за розкладом (кожні 5 хв), незалежно від вашого ПК.

Є **два окремі workflow** — оберіть один:

### 1. `monitor.yml` — тільки сповіщення (безпечний варіант)
Увімкнений за розкладом одразу після налаштування. Ніколи не відкриває
реальних угод — тільки шле сигнали в Telegram.

### 2. `autotrade.yml` — повна автоторгівля
**За замовчуванням розклад ВИМКНЕНИЙ** (тільки ручний запуск кнопкою
"Run workflow"). Це свідомий запобіжник: автоторгівля без нагляду —
серйозніший крок, навіть на testnet. Щоб увімкнути автоматичний запуск
кожні 5 хв, відкрийте `.github/workflows/autotrade.yml` і розкоментуйте
блок `schedule` на самому початку файлу.

### Покрокове налаштування

1. **Створіть репозиторій на GitHub** (github.com → New repository).
   Радимо **публічний** — необмежені безкоштовні хвилини Actions.
   Приватні теж безкоштовні, але з лімітом ~2000 хв/міс. Ваші ключі
   лишаються прихованими незалежно від публічності репозиторію.

2. **Завантажте всі файли** в репозиторій (GitHub Desktop, VS Code з
   Git, або термінал: `git init`, `git add .`, `git commit`, `git push`).
   `.gitignore` подбає, щоб `.env` не потрапив у git.

   Якщо у вас вже є локальний прогрес (`notified_setups.json`,
   `signals_log.json`, `risk_state.json`) — скопіюйте ці файли в
   репозиторій ПЕРЕД першим пушем, щоб не втратити його.

3. **Додайте Secrets** — Settings → Secrets and variables → Actions →
   New repository secret:
   - `BINANCE_API_KEY`
   - `BINANCE_API_SECRET`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`

4. **Перевірте вкладку Actions** — обидва workflow з'являться
   автоматично. Натисніть "Run workflow" на тому, який хочете
   перевірити вручну спочатку.

5. Готово — `monitor.yml` вже працює за розкладом. `autotrade.yml`
   запускайте вручну, поки не переконаєтесь, що все стабільно, і лише
   тоді розкоментуйте розклад для повної автономності.

**Обмеження:** GitHub Actions не гарантує запуск секунда в секунду —
можлива затримка в кілька хвилин. Для 1H таймфрейму це не критично.

## Шлях до реальних грошей (коли будете готові)

Це рішення виключно ваше, і воно того варте лише після тижнів
стабільної роботи на testnet із достатньою (30-50+) вибіркою закритих
угод. Коли будете готові:
1. Створіть реальні API-ключі на binance.com (не Demo Trading)
2. `BINANCE_TESTNET=false`
3. `LIVE_TRADING_CONFIRMED=true`
4. Почніть з **мінімального** депозиту, який не жалко втратити повністю

## Важливі застереження

- Це не фінансова порада. SMC-логіка тут — спрощена, тестована версія
  дискреційної концепції, не гарантія прибутку
- Бектест і live-трекінг не враховують комісії біржі та сліпедж
- 30-50+ закритих угод — мінімум для статистичної впевненості
- Сигнали на різних монетах часто корелюють (загальний рух ринку) —
  кілька одночасних сигналів в один бік не є незалежним підтвердженням
  стратегії
